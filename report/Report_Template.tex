\begin{abstract}
We develop a lightweight LLM-based shopping assistant for retrieving products
from a large Amazon product database[1]. Instead of relying on a general-purpose
LLM for the complete task, the system combines structured query extraction,
a fine-tuned product-category classifier, SQL filtering, semantic retrieval,
and recommendation generation. We compare Qwen3.5-0.8B, Llama 3.2-1B, and
Gemma 3 1B IT on a 16-class product classification task. Gemma achieves the
best result with 93.5\% accuracy and 87.4\% Macro F1. We further analyze the
latent representations before and after LoRA fine-tuning and show that
fine-tuning changes the learned representation toward the task-specific
product taxonomy.
\end{abstract}

\section{Introduction and Problem Formulation}

The goal of this project is to build a shopping assistant that converts
natural-language requests such as ``I want a wireless gaming mouse under \$50 with good reviews.'' into relevant products from a database containing approximately 1.43 million
Amazon products.

A general-purpose LLM can understand the request, but it does not guarantee
strict retrieval constraints. In exploratory tests under notebook \texttt{baseline\_llm\_query\_generator.ipynb}, a direct LLM query for a
mouse under a given price occasionally produced related products such as
mouse pads. This is acceptable for open-ended generation but undesirable for
database retrieval, where product type, category, price, and rating should be
satisfied explicitly.

We therefore decompose the problem into:

\begin{center}
\resizebox{0.95\textwidth}{!}{%
\textbf{User Query}
$\rightarrow$
\textbf{Query Parsing}
$\rightarrow$
\textbf{Category Classification}
$\rightarrow$
\textbf{Database / Vector Retrieval}
$\rightarrow$
\textbf{Recommendation}
}
\end{center}

The main deep-learning task is a closed-set multiclass problem. Given an input
text $x$, the classifier predicts
\[
\hat y=f_\theta(x), \qquad
\hat y \in \mathcal{C},
\]

where $\mathcal{C}$ contains 16 predefined Amazon main categories.

This is related to the course formulation of adapting a pretrained
language model from a generic distribution to a task-specific distribution.
The pretrained model can produce many semantically reasonable outputs, while
fine-tuning encourages outputs consistent with our specific taxonomy.

\section{Design and Methodology}

\subsection{System Design}

The system contains three main learned components. First, an LLM-based query constructor extracts structured constraints such as
product description, maximum price, minimum rating, review count, and brand. Second, a lightweight fine-tuned LLM predicts one of the 16 predefined product
categories. The category is then used as a strict database filter. Third, product-title embeddings generated using
\texttt{BAAI/bge-base-en-v1.5}~[2] represent products in a 768-dimensional
semantic latent space. Candidate products can therefore be ranked by semantic
similarity rather than exact keyword matching alone. This hybrid design combines neural language understanding with deterministic
database constraints.

\subsection{Model Selection and Motivation}

We compare three model families of similar scale:    Qwen3.5-0.8B[3], Llama 3.2-1B[4], Gemma 3 1B IT[5]. The task contains only 16 output classes and does not require long-form
generation or broad reasoning. Therefore, a small model can provide a better
cost--performance trade-off than a much larger LLM. Small models also reduce
training memory, inference latency, and dependence on external APIs.

We do not claim that 1B models are universally better than larger models.
Instead, the objective is to determine whether task-specific fine-tuning makes
a compact model sufficiently accurate for this constrained classification
task.

\subsection{Zero-Shot Prompting vs LoRA Fine-Tuning}

To setup the benchmark of LoRA fine-tuning of lightweight models, zero-shot 
prompting with GPT 5.6 was used to explicitly provide all 16 allowed category labels and 
instruct the model to output exactly one of
them. With an overall Accuracy of 0.76 and Macro F1 score of 0.61, the zero-shot approach shows moderate performance on 100 samples, while the model still does not learn the
dataset-specific boundary between categories.

For example, a base model may classify a gaming mouse as
\texttt{Computer Accessories}, while the required label is
\texttt{Electronics \& Computers}. Prompt engineering constrains the output
space, whereas fine-tuning teaches the mapping used by our dataset.

Gemma 3 1B IT was fine-tuned using supervised LoRA[6]. The pretrained weights
were frozen while low-rank trainable adapters were added to the attention
and MLP projection layers. For a weight matrix $W$, LoRA uses

\[
W' = W + BA,
\]

where $A$ and $B$ are low-rank matrices.

\section{Numerical Experiments}

\subsection{Evaluation Metrics}

Because this is a single-label 16-class classification task, Accuracy measures
overall correctness. Macro Precision, Macro Recall, and Macro F1 give equal
importance to every class and are useful when class frequencies differ.
Weighted F1 reflects overall performance while accounting for class support.
Balanced Accuracy measures average class-wise recall.

We additionally evaluate \textbf{Exact Label Compliance}, defined as the
fraction of model outputs that exactly belong to the predefined 16-label set.
This is useful for generative classifiers because a semantically reasonable
but non-standard label cannot be directly used by the downstream database.


\subsection{Classification Results}

We first evaluate whether fine-tuning is necessary by comparing the
prompt-engineered zero-shot Gemma 3 1B IT model with its LoRA fine-tuned
version. For the zero-shot baseline, all 16 valid category labels were
explicitly included in the prompt and the model was instructed to return
exactly one label. Therefore, the comparison measures more than simple
output-format control: it evaluates whether the model has learned the
dataset-specific category boundaries.

\subsection{Latent-Space Analysis}

To study whether LoRA fine-tuning also changes the model's internal
representation, we extract the final hidden representation of the same
product samples from the base and fine-tuned Gemma models. The
representations are L2-normalized and compared using cosine-distance
silhouette score in the original high-dimensional latent space. PCA is used
only for visualization.

\begin{figure}[h]
    \centering
    \includegraphics[width=0.48\linewidth]{before_latent.png}
    \hfill
    \includegraphics[width=0.48\linewidth]{after_latent.png}
    \caption{Joint PCA visualization of Gemma latent representations before
    (left) and after (right) LoRA fine-tuning. The PCA projection is used for
    visualization only; silhouette scores are computed in the original
    high-dimensional representation space.}
    \label{fig:latent}
\end{figure}

The high-dimensional cosine silhouette score improves from $-0.166$ before
fine-tuning to $-0.113$ after LoRA fine-tuning. The improvement indicates
that the learned representation becomes moderately more consistent with the
16-category structure, although the negative values show that substantial
class overlap remains.

train the same linear logistic-regression probe using frozen representations
from the base and LoRA models.

The linear probe shows a consistent but moderate improvement after
fine-tuning: accuracy increases by 5 percentage points and Macro F1 increases
from 49.18\% to 55.65\%. Together with the silhouette result, this suggests
that LoRA changes the internal representation in a direction that makes
category information somewhat more separable.

However, the improvement in latent-space linear separability is much smaller
than the improvement in the final classification task. The fine-tuned model
achieves 93.5\% end-task accuracy, while the linear probe reaches only 58.5\%.
Therefore, the classification improvement cannot be explained solely by a
global reorganization of the latent space into clearly separated linear
clusters. A possible explanation is that LoRA also adapts the later
decision and token-generation behavior of the language model, allowing it to
map existing semantic representations more effectively to the required
category labels.

\section{Discussion}

The experiments demonstrate two different effects of task-specific
fine-tuning.

First, fine-tuning strongly improves the actual category classification task.
The prompt-engineered zero-shot Gemma model reaches only 34.0\% accuracy,
even though all 16 valid categories are explicitly provided in the prompt.
After LoRA fine-tuning, accuracy rises to 93.5\%. This supports our
motivation for fine-tuning: prompt engineering can constrain the desired
output space, but it does not teach the model the dataset-specific category
boundaries.

Second, fine-tuning also changes the internal representation, but the effect
is more moderate. The cosine silhouette score improves from $-0.166$ to
$-0.113$, while linear-probe accuracy increases from 53.5\% to 58.5\%.
These results suggest that the base Gemma model already contains useful
semantic information about product categories, while LoRA partially
reorganizes or reuses this information for the specific 16-class taxonomy.

This distinction is relevant to the course concepts of task-specific
distribution adaptation and latent representation learning. The pretrained
model provides a generic language representation, while fine-tuning changes
both the task-specific output behavior and, to a smaller extent, the
geometry of the latent representation.

The results also explain why a lightweight (~1B-parameter) model
is practical for this application. Our task has short inputs and only 16
possible outputs, so the model does not need the broad generation and
reasoning capacity of a much larger LLM. Gemma 3 1B IT already reaches
93.5\% accuracy after LoRA adaptation, while requiring substantially fewer
resources than a multi-billion-parameter model. We therefore treat 1B models
as a cost--performance design choice rather than claiming that they are
universally superior to larger models.

Finally, the complete shopping task should not be delegated to a
general-purpose chatbot alone. In exploratory testing, queries such as a
request for a mouse below a fixed price could return semantically related
accessories such as mouse pads. A generative LLM optimizes semantic
plausibility, whereas our application requires strict category, price, and
rating constraints. We therefore use learned models for language
understanding and category prediction, while SQL and vector retrieval handle
the actual product search.


% =========================================================
\section{Conclusion}

We developed a modular shopping assistant combining natural-language query
understanding, LoRA fine-tuned category classification, structured database
filtering, and semantic latent-space retrieval.

The experiments show a clear benefit from task-specific adaptation. For
Gemma 3 1B IT, prompt-engineered zero-shot classification achieves 34.0\%
accuracy and 13.36\% Macro F1, while LoRA fine-tuning increases these values
to 93.5\% and 87.4\%, respectively. Among the three fine-tuned lightweight
models, Gemma also outperforms Qwen3.5-0.8B and Llama 3.2-1B, and is therefore
used in the final system.

Latent-space analysis provides a more nuanced result. Fine-tuning improves
the high-dimensional cosine silhouette score from $-0.166$ to $-0.113$ and
linear-probe accuracy from 53.5\% to 58.5\%, indicating moderate improvement
in category separability. The much larger improvement in end-task
classification suggests that LoRA improves not only representation geometry
but also the model's task-specific decision and output behavior.

Overall, the project demonstrates how a pretrained foundation model can be
adapted efficiently to a task-specific distribution using LoRA and combined
with latent-space semantic retrieval and deterministic database constraints
for a practical shopping-assistant system.
